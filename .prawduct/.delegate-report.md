## What was built, and what pins each

### 1. `os.umask(0o077)` at the one process entry — `src/bankmachine/cli/__init__.py`

Set in `run()` before argument parsing, so it is in force before anything opens a file. Every
command, `bankmachine mcp` included, is a subparser of the parser built there, and both entries
(`__main__:main` console script and `python -m bankmachine`) go through it — verified by reading
`__main__.py` and `mcp.add_arguments`. The comment carries the why (a `chmod` after the fact leaves a
window in which the file already exists world-readable; five call sites is one the sixth forgets).

Pinned by `tests/cli/test_store_commands.py::test_everything_the_product_creates_is_readable_only_by_the_operator`:
drives `store init` at `tmp_path/state/store.db` with the log at `tmp_path/state/logs` and asserts
`0o600` on the datastore, its journal files and `bankmachine.log`, `0o700` on both directories. Rooted
at directories the product creates, **not** at `tmp_path` — pytest already makes that 0700, so a test
anchored there would pass with no umask at all. Seen red before the fix (all four mode assertions).

### 3. The credential guard's vocabulary — `tests/preferences/test_no_credentials_tracked.py`

`_LABELLED` now carries the log redactor's label set: `access_token`, `refresh_token`,
`client_secret`, `api_key`, `password`, `passwd`, `secret`, `token`, `key`. `client_id` is the one
deliberate omission (configuration here, not a secret, and tracked in `.env.example`); the reason is
in the comment.

**Two deviations from the brief's wording, both measured rather than assumed:**

- **Lookarounds `(?<![A-Za-z0-9]) … (?![A-Za-z0-9])`, not `\b`.** `_` is a word character, so a `\b`
  label refuses `plaid_secret = …` and `BANKMACHINE_PLAID_SECRET=…` — the exact two spellings the
  review names as the likely leak, since the aggregator secret is the one credential the design gives
  no environment variable. Measured over the tracked tree: `\b` catches 3 of the review's 5
  demonstration rows; the lookarounds catch all 5. The trailing lookahead still keeps `key` out of
  `keychain_service` and `monkeypatch`, asserted as a negative control.
- **The value stays `[A-Za-z0-9_\-]{12,}`, not "16+ non-space".** Measured: a non-space value class
  fires on 26 lines of ordinary product code (`secret = get_plaid_secret(config)`, `key =
  func.coalesce(...)`) because the variable-reference exemption requires `value.isidentifier()`. That
  is the failure the guard's own docstring says kills a security check — "a guard that fires on
  ordinary code is a guard someone narrows in irritation later". Keeping the existing 12 rather than
  raising to 16 costs exactly one additional line tree-wide (already red at my base, see seams) and
  keeps every existing control non-vacuous: `access_token=access_token` is a 12-character value, and
  at 16 the variable-reference test would have passed for the wrong reason.

New controls: `test_every_label_the_guard_claims_is_one_it_actually_catches`, parametrized over 13
label spellings × two file shapes (`.toml` quoted, `.env` bare); and
`test_a_label_buried_inside_an_ordinary_identifier_is_not_a_label`. Every pre-existing test in the
file is unchanged and green.

### 4. Test isolation — `tests/conftest.py`, `tests/test_unservable_datastore.py`, `tests/test_config.py`

`tests/test_unservable_datastore.py` (the `_CLI_GUARDED` parametrization) now sets
`BANKMACHINE_LOG_DIR` and `BANKMACHINE_CONFIG` under `tmp_path` alongside the four it had.

`tests/conftest.py` gains an autouse fixture, `_no_test_resolves_its_paths_from_the_operators_environment`.
Its judgment is the plain function `configuration_leak(environ, base)` so it can be watched fire.

**Why this assertion and not a wider one** (the brief asked for the smallest that would have caught
the leak; the fixture docstring carries the same reasoning): the six-variable block is what every CLI
fixture sets, and the leak was one test setting four of them — the log followed the operator rather
than the datastore. So: (a) a test that sets `BANKMACHINE_DATASTORE_PATH` must also set
`BANKMACHINE_LOG_DIR`; (b) any of `BANKMACHINE_CONFIG` / `_DATASTORE_PATH` / `_LOG_DIR` that is set
must name a path inside `tmp_path_factory.getbasetemp()`. Deliberately **not** a rule that
`BANKMACHINE_CONFIG` must be set — it is the right thing to do and every CLI fixture does it, but the
leak was the log, and a guard that also fails tests for a second reason is one that gets read as noise
the first time it fires for the wrong one. `BANKMACHINE_CONFIG`'s *path* is still checked when set.

The fixture takes `monkeypatch` so its finalizer runs **before** monkeypatch's undo — otherwise there
is nothing left to inspect. That ordering is stated in the docstring.

Seen red: with the fixture in and the datastore test unfixed, all 8 parametrizations errored on
exactly the missing `BANKMACHINE_LOG_DIR`. Controls in `tests/test_config.py` (additions only, four
new tests): the leak shape, a path outside the tree, the conforming six-variable block, and the empty
environment.

## Assumptions

- `security find-generic-password -s <service> -a <account> -w` reads back what `keyring` wrote,
  because `keyring`'s macOS backend stores a generic password keyed on exactly those two fields. Not
  executed against a real keychain entry here — the tests assert the printed instruction, not the
  round trip. Cheap for the operator to confirm at cutover; worth one line in Chunk 05's day-one
  checklist.
- Setting the process umask inside `run()` leaks to the rest of a pytest process (files created after
  the first `run()` in a session are 0600 rather than 0644). Nothing in the suite asserts a 0644 mode
  — checked by grep for `st_mode` / `S_IMODE` / `0o644` across `tests/` and `src/` — so this is
  invisible outside the intended assertions.
